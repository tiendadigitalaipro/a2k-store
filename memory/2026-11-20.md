## Fix permission denied admin (2026-11-20, tarde)

- **Bug reportado por el dueño**: admin → Productos → "Nuevo producto" →
  `permission denied for table products`.
- **Causa raíz**: 00010 creó las políticas RLS admin (`products_insert_admin`
  con `WITH CHECK (is_admin())`) pero 00019 solo dio `GRANT SELECT` sobre el
  catálogo a `authenticated`. Postgres rechazaba el INSERT a nivel de
  privilegio de tabla antes de evaluar RLS.
- **Fix**: migración `00025_admin_table_grants.sql` — GRANTs INSERT/UPDATE/
  DELETE (y SELECT donde faltaba) a `authenticated` en las 25 tablas con
  políticas `*_admin` (categorías, productos, variantes, imágenes, pedidos,
  cupones, settings, etc.). Aplicada a Supabase vía Management API (25/25 OK,
  verificado con `has_table_privilege`). RLS `is_admin()` sigue siendo la
  autorización real; `anon` sigue solo-lectura (verificado).
- **De paso**: `00024_stock_rpc_authorization.sql` (commit previo, nunca
  aplicado) — REVOKE de EXECUTE a anon/auth en los 3 RPC de stock + GRANT a
  service_role. Verificado: cierra el hueco de que cualquier anónimo
  manipulara stock vía `/rest/v1/rpc/`. El checkout no se rompe:
  `create_order_checkout` los llama internamente como SECURITY DEFINER.
- Commit: `00025` local (push sigue bloqueado por token GitHub vencido).
